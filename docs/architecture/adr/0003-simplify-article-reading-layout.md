# 記事の本文幅と目次表示の簡素化

記事本文の幅を調整し、Wideの目次を常時表示する構成にした判断を記録する。

## 決定

本文幅の上限を43icとし、Wideの目次開閉を廃止した。本文と目次を横に並べ、開閉状態による本文幅の切り替えを持たない構成とした。

## 本文幅の比較

当時のArticle幅836pxに対し、Reading laneは8 / 9の約743pxだった。1icを17pxとして比較すると、40icは680px、43icは731pxとなる。Reading laneの利用可能幅をより広く使うため43icを採用した。

この換算は幅の目安であり、実際の文字数やすべてのフォントでの表示幅を保証するものではない。

## 目次開閉の比較

Wideで目次を隠す構成では、本文幅が約75px広がる一方、開閉状態、本文幅の特例、再表示操作、それぞれの検証が必要だった。本文幅を広げる効果より、状態と検証の維持負担を減らすことを優先し、常時表示を採用した。

CompactとMediumでは、目次を記事ヘッダー直後の折りたたみ領域に置く構成を維持した。

## 結果と制約

Wideでは目次を参照できる状態と本文幅を一定に保てる。読者が目次を隠して本文領域を広げる操作は提供しない。

# 解釈の違いを減らす執筆規則の採用

ASD-STE100を参考に、日本語の技術文書とUIの説明に具体的な執筆規則を採用した判断を記録する。

## 決定

用語の一貫性、一文で伝える内容の限定、主体と動作の明示、条件と結果の具体化を、リポジトリの執筆規則として定めた。ドキュメント、デザイン仕様書、確認用カタログ、UIの説明文を対象とした。

現在の規則は、ドキュメント執筆ガイドラインとUIライティングガイドラインを正本とした。規則の由来、採用時の比較、採用しなかった制約は、この意思決定ログに記録した。

## 背景

取り入れるきっかけは、Andrej Karpathyの投稿でASD-STE100を知ったことだった。LLMの出力を理解しやすくするために文章へ制約を与える考え方を参考に、このブログのドキュメントとデザインシステムの説明へ応用する規則を定めた。

ASD-STE100 Simplified Technical Englishは、英語の技術文書を理解しやすくするための標準である。執筆規則と承認語辞書を持ち、語彙と文の構造を制限して解釈の違いを減らす。

日本語のドキュメントとデザインシステムの説明にも、同じ対象を同じ名前で呼び、条件と動作を明確にする考え方を取り入れることにした。既存の簡潔さと一貫性の規則を補い、実装とレビューで何を確認するかを具体化する目的だった。

仕様の読み手に必要なのは、適用範囲と守る規則である。由来の標準を知っていることや、その名前から規則を推測できることは、仕様を理解するための前提にしなかった。

## 比較した方針

- ASD-STE100への準拠を要求する案は採用しなかった
  - 英語の承認語辞書、品詞の制限、語数の上限を、日本語へそのまま適用する目的ではないため
- 「ASD-STE100で説明する」という指示だけで規則を表す案は採用しなかった
  - 標準名をプロンプトの省略表現として使っても、このブログで守る規則と適用範囲が明示されないため
  - AIの出力を標準名で厳密に制御することが目的ではないため
- 必要な規則を日本語で明記し、由来をADRに記録する案を採用した
  - 標準の知識や文章の作成手段によらず、同じ基準で執筆とレビューができるため

## 結果と制約

- 仕様の適否は、このリポジトリに記載した具体的な規則で判断する
- この規則への適合は、ASD-STE100準拠を意味しない
- 文章の短さより、要件、例外、否定、数値、識別子を保つことを優先する
- 記事本文の語り口を、この規則で一律に制限しない
- AIによる下書きや推敲も、同じ規則で確認する。特定のプロンプトの使用は要求しない

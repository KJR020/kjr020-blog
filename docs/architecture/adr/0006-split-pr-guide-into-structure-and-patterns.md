# PR作成ガイドを構成と選んで使う型に分ける

PR作成ガイドに、レビュー観点を3段に分ける書き方を加えるにあたり、すべてのPRで従う構成と、書き手が選んで使う型を分けた判断を記録する。

## 決定

PR作成ガイドを、すべてのPRで従う構成と、PRの内容に応じて書き手が選ぶ型に分けた。レビュー観点を「問題の認識」「アプローチ」「実装の設計」の3段に分ける書き方と、概要をIssueへの参照で済ませる書き方を、選んで使う型とした。

レビュー観点を依頼ではなく観点そのものとして書く規則と、外部の根拠を切り抜いた画像で示す規則は、すべてのPRで従う構成の側に置いた。

## 背景

CIとdeployのUbuntuを24.04に固定するPR（[#168](https://github.com/KJR020/kjr020-blog/pull/168)）で、レビュー観点に既知の制約を並べただけでは、レビュアーが何を判断すればよいかが伝わらなかった。問題の認識、アプローチ、実装の設計の3段に分け、各段で判断の対象と根拠の所在を書くと、本文の抽象から具体への順と対応し、判断の材料がそろった。

一方で、手段を選ぶ余地が小さいPRで毎回3段を考え直すと、書く負担が変更の大きさに見合わない。同じように、目的と背景がIssueにある場合に概要へ背景を書き直すと、同じ内容を二重に管理することになる。

## 比較した方針

- 3段のレビュー観点を、すべてのPRで必須にする案は採用しなかった
  - 依存関係の更新のように判断する点が少ないPRでも3段を埋めることになり、内容をひねり出す原因になるため
- 書き方の例をガイドに載せず、書き手の工夫に任せる案は採用しなかった
  - [#168](https://github.com/KJR020/kjr020-blog/pull/168)の初版のように、制約の列挙で終わる書き方が繰り返されるため
- すべてのPRで従う構成と、選んで使う型を分ける案を採用した
  - 判断を伴うPRでは型を使い、小さいPRでは構成だけで済ませられるため

## 結果と制約

- 型を使うかは書き手が判断する。型を使わなくても、本文の構成を満たしていればよい
- レビュー観点を依頼ではなく観点として書く規則は、型を使うかに関わらず適用する
- 型の適用条件は、PRの内容から書き手が判断する。機械的に判定する基準は持たない

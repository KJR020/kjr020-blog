# 16列のページレイアウト採用

ページ間で主領域と補助領域の配置を揃えるため、16列を基準とするレイアウトを採用した判断を記録する。

## 決定

Wideのページシェルを16列に分け、主領域に12列、補助領域に4列を割り当てた。列は配置の基準とし、すべての領域にCSS Gridを使用する要件にはしなかった。

## 背景と選択肢

導入前の記事詳細は、可変幅の本文と固定250pxの目次で構成していた。シェル内容幅1120px、gutter 16pxでは、16列のうち12列が836px、4列が268pxとなる。既存の本文と目次の幅を大きく変えずに、ページ間で配置の基準を共有できる点を重視した。

- 12列は、16列より1列単位の幅の調整が大きくなるため採用しなかった
- 24列は、当時の領域数に対して分割が多くなるため採用しなかった
- 記事ヘッダー右側に空の250px列を確保する構成は、タイトルに使える幅を減らすため廃止した

## CSS Gridの適用範囲

ホームのヒーローを16トラックのCSS Gridで構成した際、Astro Islandの`display: contents`との組み合わせで、配置のためのラッパー要素が必要になった。

単一領域の幅は`padding-inline-end`でも実現できるため、この箇所にはCSS Gridを採用しなかった。複数領域を横に並べる記事詳細とホームの記事一覧・メモにはCSS Gridを使用した。

## 結果と制約

ページ間で配置の基準を共有しつつ、領域ごとに実装手段を選べる構成とした。実装手段が異なる箇所も、同じviewport条件で基準線が一致することを確認する必要がある。

# PR作成ガイドを原則・標準構成・パターンに分ける

PR作成ガイドを、本文が満たす原則、標準の本文構成、状況に応じて使うパターンの3層に分けた判断を記録する。

## 決定

PR作成ガイドの本文の決まりを、次の3層に分けた。

| 層 | 定めること |
| --- | --- |
| 原則 | PRの形式によらず、レビュアーと将来の読み手に伝える情報 |
| 標準構成 | 原則を満たすための、本文の基本の並びと書き方 |
| パターン | 標準構成だけでは原則を満たしにくい状況で使う書き方 |

原則には、何を、なぜ変更したかが本文から分かること、本文だけで判断の要点が分かること、判断の対象と根拠を具体的に書くこと、手段の欠点と受け入れた制約を書くことを置いた。

パターンの使う条件は、変更の種類ではなく、説明しづらい点で決めることにした。最初のパターンとして、判断を抽象度ごとに分ける書き方、背景の詳細をIssueに委譲する書き方、判断した時点の根拠を残す書き方を置いた。

標準構成の書き方には、見出しが示す役割を本文で繰り返さない規則を加えた。

## 背景

CIとdeployのUbuntuを24.04に固定するPR（[#168](https://github.com/KJR020/kjr020-blog/pull/168)）で、レビュー観点に既知の制約を並べただけでは、レビュアーが何を判断すればよいかが伝わらなかった。レビュー観点を「問題の認識」「アプローチ」「実装の設計」の3段に分け、各段に判断の対象と根拠を書くと、判断の材料がそろった。

ただし、判断する点が少ないPRで毎回3段を考え直すと、書く負担が変更の大きさに見合わない。最初の版では、ガイドを「すべてのPRで従う構成」と「選んで使う型」の2層に分けた。

その版へのレビューで受けた次の指摘に同意し、採用した。

- ガイドには、満たすべき情報、本文の並び、状況に応じた書き方の3種類が混在している。原則、標準構成、パターンの3層に分ける
- 外部の根拠を切り抜いた画像で示す規則は、すべてのPRに求めるには重い。原則は本文だけで判断の要点が分かることで、画像はそのための手段の一つである
- 概要で必ず分かるようにするのは、何を、なぜ変更するかまでにする。そうすれば、背景の詳細をIssueに委譲しても、概要だけで目的が分かる状態と両立する
- 3段に分けることは本質ではない。本質は、レビュー観点に判断の対象と根拠を書くことである。3段は、判断が複数ある場合のパターンとする

3層の原則は、Googleの[Writing good CL descriptions](https://google.github.io/eng-practices/review/developer/cl-descriptions.html)が求めること、つまり変更の内容と理由、そのアプローチを選んだ理由と欠点を本文に残すことを、抽象化したものである。

## 比較した方針

- すべてのPRで従う構成と、選んで使う型の2層に分ける案は採用しなかった
  - 満たすべき情報と、その並びと、状況に応じた書き方が混在し、新しい規則をどこに置くかの基準が決まらないため
- 3段のレビュー観点を、すべてのPRで必須にする案は採用しなかった
  - 判断する点が少ないPRでも3段を埋めることになり、内容をひねり出す原因になるため
- 書き方の例をガイドに載せず、書き手の工夫に任せる案は採用しなかった
  - [#168](https://github.com/KJR020/kjr020-blog/pull/168)の初版のように、制約の列挙で終わる書き方が繰り返されるため
- パターンを変更の種類ごとに作る案は採用しなかった
  - 変更の種類は変更の属性であり、説明しづらさは説明の属性である。パターンが働きかける対象は説明なので、条件も説明の軸で決める
  - 2つは別の軸であり、変更の種類から必要な説明は決まらない。同じCI変更でも、Actionsの更新と#168とでは、書くべき判断の量が異なる
  - 種類で分けると、PRを1つの種類へ分類する手順が必要になり、複数の種類にまたがるPRを扱えない。説明しづらい点を条件にすると、条件どうしが独立し、1つのPRで複数のパターンを使える
  - ただし、変更の種類が必要な情報を必ず決める場合は、種類で決めてよい。見た目が変わる変更で画像を貼る規則は、文章だけでは変化が伝わらないため標準構成に置いた
- レビュー観点を依頼の文にしない規則を、原則に置く案は採用しなかった
  - 原則は何を書くかで定める。依頼の文でも、判断の対象と根拠が具体的なら必要な情報はそろう
  - 依頼の文にしない理由は、見出しが伝える役割を本文で繰り返すと、伝達の層と内容の層が混ざることにある。そのため、標準構成の書き方に「見出しが示す役割を本文で繰り返さない」として置いた

## 結果と制約

- パターンを使うかは、条件に当てはまるかで書き手が判断する。機械的に判定する仕組みは持たない
- 新しいパターンは、標準構成だけでは原則を満たせなかった実際のPRから加える
- パターンの条件が変更の種類だけで書かれている場合は、その種類が必要な情報を必ず決めるかを確かめる。決めるなら標準構成へ移す

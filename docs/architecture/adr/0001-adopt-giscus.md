# コメント基盤へのGiscus採用

Astro製技術ブログのコメント基盤にGiscusを採用した判断を記録する。現在の構成と設定は[コメント機能](../comment_architecture.md)を参照する。

## 決定

コメント基盤にGiscusを採用した。専用サーバーを運用せずに静的サイトへ組み込めること、GitHub認証とMarkdownによる投稿に対応することを重視した。

## 採用時の前提

以下は採用時の要件と配信構成であり、現在のホスティング環境を示すものではない。

- Astroで静的生成し、GitHub Pagesで配信する
- 全記事にコメント欄を設ける
- コメント機能のために専用サーバーを運用しない
- 認証方式はGitHub認証を優先する
- コメント基盤の利用料金と保守負担を抑える
- Markdownとコードブロックで技術的な内容を投稿できることを重視する

## 検討した選択肢

既存の選定記録に挙げられていた候補を、判断に用いた観点とともに整理する。各サービスの最新の料金・機能を比較する一覧ではない。

| 方式 | 候補 | 判断の観点 |
| --- | --- | --- |
| GitHub Discussionsを利用 | Giscus | 専用サーバーを持たず、GitHub上でコメントを管理できる |
| GitHub Issuesを利用 | Utterances | GitHubをコメントの保存先・認証基盤として利用できる |
| セルフホストを含む方式 | Cusdis、Remark42、Commento/Comentario、Isso | 自前でホストする場合、運用・監視・更新が必要になる |
| 外部のコメントサービスを利用 | Disqus、Hyvor Talk | 利用料金、広告の有無、データの管理方法を確認する必要がある |

元の記録にはUtterancesを採用しなかった個別の理由は残されていない。この記録では、Giscusが満たす要件と採用に伴う制約を示す。

## 採用理由

- 静的サイトへの埋め込みでコメント機能を提供できる
  - コメント保存用のサーバーやデータベースを運用する必要がないため
- GitHub認証とMarkdownによる投稿に対応する
  - 技術的な内容をコードブロックとともに投稿する用途を満たすため
- コメントをGitHub Discussionsに保存する
  - 管理対象のリポジトリにコメントを集約し、GitHub上で管理できるため
- テーマをサイトのライトモード・ダークモードに合わせられる

## 採用に伴う制約

- 投稿者にはGitHubアカウントが必要になる
- コメント機能はGiscusとGitHub Discussionsに依存する
- 不適切な投稿への対応は運営者が行う必要がある
  - GitHub認証の利用だけでスパム対策が完結するわけではないため

## 再検討の条件

- GitHubアカウントの必須化が読者の投稿を妨げていると確認された場合
- GitHub Discussionsでの管理が運用上の負担になった場合
- 匿名投稿やGitHub以外の認証方式が必須になった場合
